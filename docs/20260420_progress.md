# SRCNN 120×120 전환 진행 기록 (2026-04-20)

## 요약

프레임/타일 크기를 **150×150 → 120×120** 로 전환해 L3 Mode B의 99.87% gap을 **정확히 100.00%** 로 제거. UHD는 120 타일 576개로 깔끔 분할 (padding 0). 전 5 config × 전 layer × 전 픽셀에서 HW=SW bit-exact, max_diff=0.

**RTL 변경 없음** — 기존 `mode_b_pass_20260418.bit` 그대로 유효. 모든 수정은 SW/데이터/스크립트.

---

## 배경: 99.87%는 왜 생겼는가 (2026-04-20 오전 분석)

150×150 입력에서 L3 Mode B의 PE util이 99.87%로 측정돼 왔음. 분석 결과:

```
150 × 150 = 22,500 pixel
Mode B batch = 64 pixel/tile
22,500 ÷ 64 = 351.5625 → ceil = 352 tile
352 × 64 = 22,528 pixel slot  (28 dummy padding 포함)

util = useful_macs / (pe_cycles)
     = (22,500 × 36) / (22,528 × 36)
     = 22,500 / 22,528
     = 99.876%  ≈ 99.87%
```

결론: **HW 한계가 아니라, 입력 픽셀 수가 64의 배수가 아니어서 발생하는 구조적 padding overhead**. 이미지 크기만 64의 배수로 맞추면 100% 달성 가능.

**120×120 = 14,400 = 225 × 64** ✓ 정확히 나눠떨어짐.
**UHD 3840÷120=32, 2160÷120=18** ✓ 576 타일 완전 분할.

## 발견·해결한 버그 2개

### 버그 1: im2col MAX_BATCH_ROWS=16 초과 (TIMEOUT)

**증상**: 120 버전 첫 빌드에서 전 config L1 pass0 bs=0에서 TIMEOUT.

**원인**: `hwpe_im2col.sv` L120: `load_row_q [3:0]` (0..15 index). 한 batch당 최대 16 row 로드.
- 150 때: bp_pad=1808, img_w=150 → 행 수 ≈ 14. OK.
- 120 때: bp_pad=1808, img_w=120 → 행 수 = ceil(1808/120)+2 ≈ **17**. **16 초과 → FSM stuck**.

**해결**: SW에서 batch 크기에 cap 걸어 row 수를 16 이하로 유지.
```c
int row_cap_bp = 14 * IMG_W;  // 첫 시도
```

### 버그 2: row_cap_bp가 SA_COLS=16 배수 아님 → batch overwrite

**증상**: row_cap=13×IMG_W 로 강화한 뒤, 120 single-frame에서 L1 util 99.44%, exact 5835/14400, max_diff=188. UHD는 40.97% exact.

**원인**: `row_cap_bp = 13 * 120 = 1560`, `1560 / 16 = 97.5` → **16의 배수 아님**. Mode A 에서:
- `bp = 1560` 이지만 `bp_pad = ceil(1560/16)*16 = 1568` → HW가 1568 pixel 씀 (뒷 8개는 dummy)
- 다음 batch는 `bs += 1560` 으로 전진 → **이전 batch 끝 8 dummy 가 다음 batch 시작 덮어씀** → 출력 오염

이전 `14 × 120 = 1680 = 105×16` 이 우연히 16 배수라 노출 안 됐음. 13에서 drop-through.

**해결**: row_cap_bp 를 SA_COLS 배수로 align-down.
```c
int row_cap_bp = 13 * IMG_W;
row_cap_bp = (row_cap_bp / SA_COLS) * SA_COLS;
// 120 → 1552,  126 → 1632
```

### 부수 소득

- UHD 첫 실패(40% exact) 원인도 이 SA_COLS align 버그였음. 해결 후 UHD도 8.29M bit-exact.
- HWPE 자체는 이 버그와 무관 (SW의 CSR 설정 문제였음) → RTL 재합성 불필요.
